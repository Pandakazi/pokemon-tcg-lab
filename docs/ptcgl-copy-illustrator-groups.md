1. **Previous mismatch.** Copy Deck List formatted `quantity name (internal printing_id)`. TCG Live expects a set code and collector token after the name. There was no existing PTCGL serializer/importer in the repository to reuse. The old helper was a human-readable plain-text formatter. The `Total Cards` footer itself is compatible and is retained; internal IDs and parentheses are removed from clipboard output.
2. **Serialization.** The existing copy action now calls a read-only `POST /api/v1/decks/export-ptcgl` with `{cards:[{printing_id,quantity}]}`. A single backend serializer resolves canonical names, categories, set codes and collector tokens locally; the client supplies no name/category/code overrides. It emits Pokémon, Trainer, Energy sections and `quantity name code number` lines, followed by the total. Section headings count distinct exported lines, as in Live-style exports; the actual quantity/category totals remain unchanged and are returned separately. Identical external lines may merge by summing quantities, with no internal allocation mutation. Failure is all-or-nothing; no partial/malformed list reaches the clipboard. A pending state prevents duplicate export clicks. Copied confirmation remains lightweight; export errors and any substitution notice are visible beside the action.
3. **Metadata.** Local SQLite `cards.raw` provides `name`, `localId`, category and Basic Energy metadata; `sets.raw` supplies `tcgOnline`, falling back to `abbreviation.official`. No guessed translation from printing-ID/set-ID string patterns is used. The lookup is limited to requested printings and local Basic Energy candidates. The endpoint does not initialize collection/deck state or write any database.
4. **Special cases.** Numeric collector tokens remove only leading zeros (`071` → `71`). Alphanumeric tokens such as `TG01` and `GG01` remain unchanged. Online metadata supplies the base code for subsets (`BRS TG01`, `CRZ GG01`), rather than serializing physical `BRS:TG` abbreviations. Special sets such as PRE/SFA use their local official codes. SVP promos are supported via local SVP metadata. Missing online/official mappings, unsafe tokens or unavailable collector metadata block export explicitly; no fabricated promo mapping is added. Basic Energy uses the existing curated type recognition and Live names such as `Basic {D} Energy`. Representable exact Energy printings retain their local code/number (e.g. MEE 2). Unrepresentable Basic Energy, including physical trainer-kit printings, may use a locally indexed equivalent SVE printing of the same curated type; the UI reports that export-only substitution and states allocations are unchanged. No available equivalent means export fails. Special Energy never receives a Basic Energy substitution.
